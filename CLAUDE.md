## Project Overview

STM32H750 Field Oriented Control (FOC) motor controller with support for up to 3 motors. Uses FreeRTOS, implements dual-loop control (20kHz current loop, 1kHz velocity loop), and features real-time debugging via VOFA+ protocol.

## Build System

**Primary build tool:** CMake with GCC ARM toolchain

```bash
# Configure build
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# Build project
cmake --build build

# Flash to target (requires ST-Link)
# Use STM32CubeProgrammer or openocd
```

**Alternative:** Keil MDK project files in `MDK-ARM/` directory

**Key dependencies:**
- STM32 HAL drivers (auto-generated by STM32CubeMX)
- FreeRTOS V10.3.1
- CMSIS-DSP library (for floating-point operations)

## Architecture

### Layered Design

```
Application (main.c)
    ↓
Motor Object Layer (motor.h/.c) - Unified control interface
    ↓
FOC Control (FOC.h/.c) + Hardware Abstraction (motor_hardware.h/.c)
    ↓
STM32 HAL (TIM, ADC, DMA, GPIO)
```

### Control Loop Structure

- **High-frequency current loop:** 20kHz, triggered by ADC1 DMA completion interrupt
- **Low-frequency velocity loop:** 1kHz, triggered by TIM7 period elapsed interrupt

**Critical timing:** FOC calculations run in interrupt context at 20kHz (50μs period). All floating-point math requires FPU enabled in interrupt mode.

### Key Modules

**FOC.h/.c** - Core FOC algorithm
- Clarke/Park coordinate transforms (abc → αβ → dq)
- PID controllers (d-axis, q-axis current; velocity)
- SVPWM modulation using Min-Max zero-sequence injection
- Control modes: Torque (direct Iq), Velocity (PID), Open-loop

**motor.h/.c** - Motor object abstraction
- Encapsulates FOC controller + hardware resources
- Multi-motor support (Motor_TypeDef instances)
- State management and error handling

**motor_hardware.h/.c** - Hardware abstraction layer
- PWM driver interface (pwm_driver.h/.c)
- Current sensing interface (current_sense.h/.c)
- Encoder interface (encoder.h/.c)

**encoder.h/.c** - Incremental encoder driver
- Quadrature decoding (default 1024 PPR)
- Speed calculation (RPM/RPS)
- Electrical angle calculation
- Z-pulse home detection

**current_sense.h/.c** - Three-phase current sampling
- ADC DMA circular buffer management
- Zero-point calibration (critical for accuracy)
- Low-pass filtering
- Converts ADC values to amperes

**vofa_debug.h/.c** - Real-time visualization
- JustFloat protocol (8 float channels)
- DMA-based UART transmission
- For monitoring FOC variables during operation

## Hardware Configuration

**MCU:** STM32H750VBT6 (Cortex-M7 @ 480MHz)

**Peripherals:**
- TIM1: PWM for Motor 0 (20kHz, channels 1-3 for U/V/W phases)
- TIM3: Encoder input for Motor 0 (quadrature mode)
- TIM7: Velocity loop timer (1kHz)
- TIM8: PWM for Motor 1
- ADC1: Current sampling Motor 0 (3 channels, DMA circular, triggered by TIM1 TRGO)
- ADC2: Current sampling Motor 1 (3 channels, DMA circular, triggered by TIM1 TRGO2)
- UART4: Serial communication (115200 baud) for debugging/commands

**Memory layout:**
- DTCM RAM: 0x20000000 (128KB) - Used for DMA buffers
- AXI SRAM: 0x24000000 (512KB)
- **Important:** CurrentSense_TypeDef must be placed in DTCM RAM to avoid DMA access issues on STM32H7

## Critical Implementation Details

### FPU Requirement
Floating-point FOC requires FPU enabled in interrupt context. This is configured in main.c:
```c
SCB->CPACR |= ((3UL << 10*2)|(3UL << 11*2));  // CP10 and CP11 Full Access
```
**Never remove this** - causes HardFault if missing.

### DMA Memory Constraints
STM32H7 DMA cannot access DTCM RAM (0x20000000). CurrentSense_TypeDef buffers are placed at 0x30020000 (D2 SRAM). If you see DMA transfer errors or garbled UART data, check memory placement.

### Interrupt Priority
- ADC DMA completion (current loop): Highest priority
- TIM7 (velocity loop): Lower priority
- UART: Lowest priority

### PWM Configuration
- Frequency: 20kHz (ARR = 2999)
- Dead time: 100 ticks (~417ns) for IR2010S gate driver
- Complementary outputs with dead-time insertion

### Current Sensing
- 16-bit ADC resolution
- Sensitivity: 0.165 V/A
- **Zero-point calibration required** before enabling FOC
- Sampling synchronized with PWM center-aligned mode

## Common Workflows

### Adding a New Motor
1. Create Motor_TypeDef instance
2. Configure MotorHAL_TypeDef with hardware resources (timer, ADC, encoder)
3. Set MotorParams_TypeDef (pole pairs, voltage, current limits)
4. Call Motor_Init()
5. Add Motor_UpdateSensors() and Motor_UpdateCurrentLoop() to interrupt handlers

### Modifying FOC Parameters
- Current loop PID: FOC.c:297-300 (Kp=1.0, Ki=50.0, Kd=0.0, Ts=50μs)
- Velocity loop PID: FOC.c:304 (Kp=0.5, Ki=2.0, Kd=0.01, Ts=1ms)
- Limits: FOC.h defines FOC_VOLTAGE_LIMIT, FOC_CURRENT_LIMIT, FOC_VELOCITY_LIMIT

### Debugging Motor Issues
See `docs/DEBUG_INSTRUCTIONS.md` for systematic troubleshooting steps. Key checks:
1. Verify ADC interrupt entry (LED toggle test)
2. Verify FOC enabled flag
3. Check PWM duty cycles are non-zero
4. Monitor current values for overcurrent

### Calibration Procedure
1. Call CurrentSense_Calibrate() with motor stationary (100 samples)
2. Optionally run Forcejiaozhun() for open-loop encoder alignment
3. Enable FOC and gradually increase target velocity

## STM32CubeMX Integration

**Configuration file:** h7FOC.ioc

When regenerating code with STM32CubeMX:
- Preserve user code sections in main.c, stm32h7xx_it.c
- Verify ADC DMA trigger sources (TIM1 TRGO/TRGO2)
- Check TIM1 dead-time configuration
- Ensure FreeRTOS heap size is adequate (15360 bytes)

**After regeneration:** Rebuild with CMake to update cmake/stm32cubemx/CMakeLists.txt

## Code Modification Guidelines

### Timing-Critical Code
Code in ADC DMA callback (20kHz) must execute in <50μs. Avoid:
- Blocking calls (HAL_Delay, printf)
- Heavy computation
- Non-inlined function calls

### Floating-Point Performance
Use arm_math.h functions from CMSIS-DSP for optimized operations:
- arm_sin_cos_f32() for trig
- arm_sqrt_f32() for square root
- arm_atan2_f32() for angle calculation

### Multi-Motor Considerations
Each motor needs independent:
- TIM for PWM
- ADC channels for current sensing
- TIM for encoder (or separate encoder interface)
Ensure no resource conflicts.
