## 2026-04-17（风险修复批次）

### 范围
- `comm/protocol/comm_ecat_if.c`

### 修复项
1. 自愈重启前增加资源清理：
   - 设置 `bRunApplication = FALSE`
   - 调用 `CiA402_DeallocateAxis()` 后再执行 bootstrap
2. bootstrap 部分失败回滚：
   - `CiA402_Init()` 成功但 `APPL_GenerateMapping()` 失败时，执行 `CiA402_DeallocateAxis()`
3. 修复 `mode_display` 语义不一致：
   - `objModesOfOperationDisplay` 改为写入 `mode_display`
4. 增加 not-ready 周期重试初始化：
   - `comm_ecat_if_process()` 中每 1000 tick 触发一次 `comm_ecat_if_init()` 重试

### 代码分析
1. 初始化返回值风险：
   - `comm_ecat_stack_bootstrap()` 已显式检查 `MainInit/CiA402_Init/APPL_GenerateMapping`，失败即返回 0，不会误置 ready。
2. 自愈重启资源风险：
   - 原流程可能重复执行 CiA402 初始化并累积资源；现在加入重启前清理与部分失败回滚，避免长期资源退化。
3. 初始化永久熔断风险：
   - 通过 not-ready 周期重试，瞬时故障恢复后可自动再次初始化，无需重启系统。
4. TXPDO 接口一致性：
   - `mode_display` 计算结果与最终写回字段统一，避免接口语义漂移。

## 2026-04-17（审查修复批次2）

### 范围
- `comm/protocol/comm_ecat_if.c`
- `Core/Src/stm32h7xx_it.c`

### 修复项
1. 修复 EXTI 回调重复定义导致的链接冲突：
   - 将 `Core/Src/stm32h7xx_it.c` 中的 `HAL_GPIO_EXTI_Callback` 更名为内部占位函数，保留 `Core/Src/main.c` 作为唯一 HAL 回调实现。
2. 修复 EtherCAT 健康自愈路径潜在重复释放：
   - 新增 `comm_ecat_release_cia402_axis()`，通过 `g_cia402_axis_allocated` 做幂等释放保护。
   - `comm_ecat_health_poll()` 中改为调用幂等释放接口，避免连续失败场景下重复 `CiA402_DeallocateAxis()`。
3. 修复 `force_reinit` 资源生命周期缺口：
   - `comm_ecat_if_force_reinit()` 中加入 CiA402 资源释放，确保下一次初始化前处于干净状态。
4. 补齐 `mode_display` 语义一致性：
   - `comm_ecat_update_feedback_to_cia402()` 优先使用 `objModesOfOperationDisplay`，必要时回退到 `objModesOfOperation`。
   - `comm_ecat_if_fill_txpdo()` 的回退值改为 `objModesOfOperationDisplay`。

### 代码分析
1. 关于初始化返回值与 ready 状态：
   - 当前 `comm_ecat_stack_bootstrap()` 已检查 `CiA402_Init()` 与 `APPL_GenerateMapping()` 返回值，失败不会置 ready。
   - 本批次未改变该逻辑，作为基线继续保留。
2. 关于重复释放风险：
   - 原始路径中，健康检查每轮失败都可能再次触发 `CiA402_DeallocateAxis()`。
   - 而 `CiA402_DeallocateAxis()` 释放后未把 `ObjDic` 清空，重复调用存在 double-free 风险。
   - 幂等释放标志将释放动作限制为“仅在已分配时执行一次”，消除该风险。
3. 关于强制重初始化一致性：
   - 仅把 `ready` 清零而不释放资源，会让下一轮初始化在“旧资源未彻底退出”的上下文执行。
   - 在 `force_reinit` 中补释放后，重启链路与健康自愈链路的资源语义一致，行为可预测。
4. 关于模式显示字段一致性：
   - `mode_display` 应对应“显示态”对象，不应混用“目标模式”对象。
   - 统一回读/回写字段后，TXPDO 快照接口和对象字典字段语义一致，便于后续扩展与诊断。

## 2026-04-17（审查修复批次3）

### 范围
- `comm/protocol/comm_ecat_if.c`

### 修复项
1. 调整 SYNC0 ISR 默认行为：
   - `COMM_ECAT_SYNC0_APPLY_IN_ISR` 默认值由 `1` 改为 `0`。
   - 默认改为“ISR仅记录事件，命令在主循环处理”，降低中断上下文负载和抖动风险。
2. 修复健康自愈失败后的状态语义：
   - 在 `comm_ecat_health_poll()` 进入自愈时先置 `g_ecat_ready=0`、`g_ecat_failed=1`。
   - 自愈成功后恢复 `g_ecat_ready=1`、`g_ecat_failed=0`。
   - 自愈失败保持 not-ready，让 `comm_ecat_if_tick_1ms()` 走统一重试路径。

### 代码分析
1. 关于 ISR 负载：
   - 在 SYNC0 中断内直接执行 CiA402 命令应用会引入分支、模式切换和目标写入等非短路径逻辑。
   - 对 FOC 场景，中断路径应尽量短，默认迁移到主循环应用更稳健。
2. 关于 `ready` 与资源生命周期一致性：
   - 原先恢复失败后可能出现“资源已释放但ready仍为1”的状态不一致。
   - 将 `ready` 与恢复结果绑定后，状态机和实际资源一致，避免后续流程误判可用性。
3. 关于重试闭环：
   - 失败后进入 not-ready，复用已有 `tick_1ms` 初始化重试机制，减少多套恢复路径并提升可维护性。

## 2026-04-17（Modbus兼容性回归）

### 范围
- `comm/protocol/comm_modbus_regs.h`
- `comm/protocol/comm_od.c`

### 兼容修复项
1. 对齐 TEST1/DriverStudio 旧地址映射：
   - 命令区补齐 `0x0204(SetZero)`、`0x0205(ClearFault)`。
   - 将 EtherCAT 重初始化命令迁移到 `0x0206`，避免与 `SetZero` 冲突。
2. 补齐运动参数地址（保持可读可写）：
   - 新增 `0x0305(target current)`、`0x0307(accel)`、`0x0309(decel)`、`0x030B(runtime)`。
3. 补齐三环调参地址（0x0400~0x0420段）：
   - 支持 `0x0401/0x0403/0x0405`、`0x0411/0x0413/0x0415`、`0x0421/0x0423/0x0425` 的读写。
4. 遥测兼容补齐：
   - `0x0202`、`0x0203` 支持 03 读回（使能/运动状态），避免上位机轮询时报非法地址。

### 代码分析
1. 根因：
   - 当前固件在 EtherCAT 集成后扩展了 Modbus 映射，但与 TEST1 和 DriverStudio 的历史寄存器存在冲突与缺失，典型冲突是 `0x0204` 语义变化。
2. 风险：
   - 上位机执行 `06/10` 写入 `0x0204`、`0x0305`、`0x0401` 等地址时会得到非法地址异常，表现为“功能失效”。
3. 修复策略：
   - 采用“兼容扩展”而不是“替换重构”：保留原控制逻辑，增加历史地址别名与回读回写路径，避免影响现有控制环执行。
4. 影响面：
   - Modbus RTU 对旧上位机的地址兼容性恢复；
   - 控制核心（FOC内环/外环）未改动，仅增加寄存器映射与兼容缓存变量。
